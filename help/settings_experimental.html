Experimental

The Experimental window holds the theme, the icon and emoticon packages and every option that DC++ Experimental adds to DC++; the Settings dialog keeps the options of DC++ itself. Open it from View > Experimental, or with the button on the Experimental page of Settings (which closes Settings as OK does). Its tabs are Themes, Icons, Emoticons, Chat and sharing, Transfers and hashing, Private Send, Protocol limits and Other. Each tab shows its groups in two columns when the window is wide enough and in one otherwise, and scrolls when the window is too small for it. The box at the bottom shows the help for the option that has the focus.

Changes apply at once, without an OK button: check boxes and lists when they change, and number and text fields after a short pause in typing, when Enter is pressed or when the field is left. A number field keeps its value within the allowed range, and text that isn't a number is replaced by the current value when the field is left. Settings are saved automatically shortly after a change.

Themes

The Themes tab sets the light or dark mode, the theme and the fonts and colors of the interface, lists, chat and user matching definitions, with a live chat preview. See Themes.

Icons

Icon packages
The icons DC++ uses in its menus, toolbar, tabs and lists. Select a package to preview its icons on a light and on a dark background, at the size chosen above the preview; point at an icon to see its name. Use this package (or a double click) switches to it; windows that are already open keep their icons until DC++ restarts. Automatic uses Dark.dcico in a dark theme and the icons built into DC++ otherwise; Embedded icons always uses the built-in ones. An icon a package doesn't have is shown from the built-in set. Packages are .dcico ZIP files containing info.xml and multi-resolution ICO files, kept in the IconPacks folder (Open folder); Browse uses one from elsewhere and Reload lists the folder again. Each package is unpacked once, into the Extracted folder of DC++'s local data folder (beside DCPlusPlus.exe in the portable version), and read from there.

Emoticons

Emoticons
Enable emoticons in chat turns emoticons on or off. Choose the emoticon package (.dcemo), the size emoticons are shown at and the preferred bit depth of their images; the list on the right shows what the selected package contains. Browse uses a package from elsewhere, Build makes one from images, and Import XML converts an older XML emoticon package. Choose Custom / edit selected in the package list to add, change or remove emoticons.

Package extraction limits

An emoticon package (.dcemo) is a ZIP file. It is unpacked once, the first time it is used or after it changes, into the Extracted folder of DC++'s local data folder, and read from there. These limits stop a crafted package from filling the disk: unpacking stops with an error as soon as one is exceeded, counting the data actually decompressed. A package unpacked earlier is checked against the current limits as well.

Maximum package entries
The most files and folders a package may contain. Range: 1 to 65535. Default: 4096.
Maximum extracted file size
The largest any single file in a package may be once unpacked, in KiB. Minimum: 1 KiB. Default: 16384 KiB (16 MiB).
Maximum total extracted size
The most all files in a package together may take up once unpacked, in KiB. Minimum: 1 KiB. Default: 131072 KiB (128 MiB).

Chat and sharing

Enable ADC RTF0 CommonMark chat
Announces support for rich text chat (the ADC RTF0 extension) on hubs and in direct encrypted private chats, and shows rich text messages formatted, using a safe subset of CommonMark. Chats with other RTF0 clients get the rich text editor and attachments by drag and drop. Default: on.
Enable temporary file sharing in chats
Lets you share a file without adding it to your share: drop it on a hub chat or a private chat, on ADC or NMDC hubs, or attach it in the rich text editor. DC++ hashes it and posts a magnet link, which shows the file's size and can be clicked. A file shared in hub chat can be found by exact TTH search and downloaded on that hub only; a file sent in a private chat is available to that user only and never appears in searches. These files are never part of your file list or share size. Turning this off stops new temporary shares and makes the existing ones unavailable; they stay in the list of active temporary shares until removed or DC++ exits. Default: on.
Insert dropped image files as inline media
In a chat with rich text support, a dropped image (BMP, GIF, ICO, JPEG, PNG, TIFF or WebP) is inserted as an inline image. Other chats always get a magnet link. Default: on.
Rich text message size limit
The largest rich text message, sent or received, in KiB of UTF-8 text. A larger incoming message is replaced with a notice that it was left out; a larger draft can't be inserted into chat. Minimum: 1 KiB. Default: 64 KiB.
Clickable chat link length limit
The longest web address or magnet link that is made clickable in chat; a longer one is shown as plain text. Minimum: 1 character. Default: 256 characters.
Maximum temporary shares
How many files can be shared in chats at once. When the limit is reached, the file shared or reused longest ago stops being shared. Range: 1 to 10000. Default: 256.
Automatically remove temporary shares after
Stops sharing a chat file this many minutes after it was last added to a chat. It only ends searches and downloads of it: the file itself, the messages already posted and your normal share are not touched. A change applies to files already shared too. 0 keeps them shared until they are removed or DC++ exits. Default: 0.
Active temporary shares
The files currently shared in chats, with their size, where they were shared (a hub, or a private chat with a user), their TTH and their location on disk. Remove selected and Clear all stop sharing them; Refresh checks again whether the files are still there. Files shared in chats are kept for this session only.

Transfers and hashing: file lists

Largest file list to download
The largest full file list downloaded from another user, in MiB, as that user announces it: the size of the compressed .bz2 file, or of the XML when the list is sent as XML. A larger list is refused before anything is written to disk, and so is a list larger than the largest file list to open, since it could not be opened. 0 means no limit. Default: 512 MiB.
Largest file list to open (XML)
The most XML a file list may contain when it is opened, in MiB; it protects against lists that need a great deal of memory. This is Max filelist size in Settings > Advanced > Experts only, shown here too. 0 means no limit. Default: 512 MiB.
Generated partial file list limit
The largest partial file list DC++ makes when another user browses a folder of your share, in KiB of uncompressed XML. A request for a larger list is refused. Minimum: 1 KiB. Default: 65536 KiB (64 MiB).
Received partial file list limit
The largest partial file list accepted from another user, in KiB of uncompressed XML. Partial lists are kept in memory while they download, and a compressed transfer can expand a little data into a very large list, so a larger list is refused before it is received. A list of a folder and everything in it that is over the limit is downloaded as a full file list instead, which is saved to disk. Minimum: 1 KiB. Default: 393216 KiB (384 MiB).
Prefer Zstandard over zlib when the peer supports both
Downloads from a client that supports both zlib and Zstandard compression (the experimental ZST1 extension, on ADC or NMDC) use Zstandard. Without this, zlib is used then; a client that supports only Zstandard gets Zstandard either way, and other clients are unaffected. Full file lists asked for with Zstandard are sent as compressed XML instead of bzip2. Nothing is compressed unless Enable safe and compressed transfers is on (Settings > Advanced). Applies to new download requests. Default: off.
Cache file lists on disk and load file entries on demand
When a file list is opened, DC++ builds a compressed index of it on disk and keeps only the folders in memory; the files of a folder are loaded when you open it and released when you leave it. This saves memory with very large lists, at the cost of disk space. The first opening builds the index, later ones reuse it until the list changes, and the original list is kept. Searching the list, matching it against the queue, ADL Search and downloading folders include files not loaded. A single very large folder still needs memory for its own files. Applies to lists opened afterwards. Default: off.

Transfers and hashing: multi-connection transfers (MCN)

Maximum regular download connections per user
How many regular connections DC++ opens to one user to download from them at the same time (the ADC MCN1 extension). The other user's own limit, announced as CO, is respected too; no CO, or CO0, means they have no separate limit. The connections can download different files, and different parts of one file when segmented downloading is on. Range: 1 to 100. Default: 2.
Maximum regular upload connections per user
How many regular connections one user may use to download from you at the same time (MCN1); DC++ announces this number to clients that support it. Upload slots count users, not connections: a user with several connections takes one slot, and their extra connections are given up when another user needs a slot. Range: 1 to 100. Default: 2.
Priority connection
MCN1 also keeps one more connection per user for partial file lists and files smaller than 64 KiB, so they don't wait behind large files. It counts toward neither limit above nor the upload and download slots. Full file lists, file trees and larger files always use regular connections.

Transfers and hashing: hashing and share database

Maximum hash speed
Limits how fast files are read for hashing, in MiB/s for each drive being hashed. 0 means no limit. Default: 0.
Drives hashed at the same time
Files on different drives, or on different network shares, are hashed at the same time, up to this many drives at once. Each drive is still read one file at a time, so a hard disk or a NAS never has to seek between files. When more drives are waiting, they take turns. Use 1 to hash one file at a time across all drives. Range: 1 to 16. Default: 2.
Hashing worker threads
How many processor threads may calculate the hash of one file. The file is still read in order, and SFV checks keep their order. DC++ uses fewer threads for a file with few blocks, on a computer with fewer logical processors, or when more would need over 256 MiB of memory. Use 1 to hash with a single thread. Range: 1 to 64. Default: 2.
Hash database write batch size
How many changes to the hash database are written together in one transaction. Larger values hash large shares faster; smaller values save each newly hashed file sooner. Minimum: 1. Default: 256.
Report each hashed file in the system log
Adds a line to the system log for every file that is hashed. When this is off, hashing reports one summary per folder instead, which keeps the system log readable while a large share is hashed. Default: off.
Verify hash database on startup
Runs a quick SQLite integrity check of the hash database when DC++ starts. If it fails, the damaged database is renamed and a new one is started, so shared files are hashed again. Default: off.
Compact hash database after rebuild
Gives back the disk space the hash database no longer needs after it has been rebuilt. Default: off.
Use cached share tree on startup
At startup, DC++ shares the folder tree it saved last time while it scans your shared folders again in the background, for local, mapped and network (\\server\share) folders alike. Loading it reads none of the shared files, so it is quick even for very large shares on network drives. Default: on.
Verify, Full check, Optimize, Compact
Maintains the hash database at once. Verify runs a quick integrity check (SQLite quick_check), Full check a thorough one (integrity_check), Optimize updates the statistics SQLite uses to plan queries, and Compact writes out the log of pending changes and gives back unused disk space.

Private Send (experimental PFT1)

Private Send offers a file directly from a private chat, without a search result, a file list or a public magnet link. Both clients must support the same experimental draft and be connected through an ADCS (secure) hub, with a direct encrypted private chat using TLS 1.2 or later (with ECDHE and authenticated encryption). After turning it on, reconnect an existing direct chat so the two clients agree on it. Open Private Send... from the chat's menu, or click the file icon in the status bar of the private chat; it can be opened before the direct connection or contact verification is ready.

The recipient accepts each file. A received file is fully verified against its hash and passes Windows' attachment checks before it is saved below PrivateSend\Received in DC++'s local data folder; it is never opened or shared automatically. A paused transfer can be resumed by the recipient for up to 30 minutes, within the transfer's time limit, at most three times. Clear list removes finished, canceled, declined, expired and failed transfers of this contact; active and paused ones stay, and saved files are kept.

When an offer or a transfer expires, access ends and an incomplete received file is deleted; the sender's original and a completed received file are never deleted. Transfers do not survive a restart. PFT1 is a proposed protocol: it is not yet known to work with other clients and has not had an independent security review.

Enable Private Send (requires TLS 1.2+)
Turns Private Send on for direct encrypted private chats. Turning it off ends all Private Send transfers. Default: off.
Require contact verification (off for testing)
When on, each of you chooses Add contact to check the other client's certificate against the identity the current secure hub announces for them, and to remember it; or use Details > Compare fingerprint... to compare a CID and fingerprint obtained another way. Turning it on cancels transfers with a contact whose fingerprint has not been approved, and forgetting a verified contact ends their transfers. When off, as for testing, contacts are not checked, and they are not saved as verified either. Default: off.
Offer expires after
How long a new offer of yours waits to be accepted. Range: 1 to 1440 minutes. Default: 15 minutes.
Accepted transfer expires after
How long an accepted transfer may take. When the two clients' limits differ, the earlier one applies. Changing this never extends a transfer already under way. Range: 1 to 10080 minutes (one week). Default: 1440 minutes (one day).

Protocol limits: direct private-message channels (CCPM)

These options control how DC++ reconnects a direct encrypted private chat that was lost. Each failed attempt waits longer than the one before, with a little randomness, so two clients don't retry at the same moment.

Initial automatic reconnect delay
How long DC++ waits before the first attempt to reconnect; later attempts wait longer. Range: 1 to 3600 seconds. Default: 5 seconds.
Maximum automatic reconnect delay
The longest DC++ waits between attempts. A value below the initial delay is raised to match it. Range: 1 to 3600 seconds. Default: 60 seconds.
Stable connection reset time
How long a direct chat must stay connected before the count of attempts starts again from zero. Range: 1 to 86400 seconds. Default: 60 seconds.
Maximum automatic reconnect attempts
How many times DC++ tries to reconnect on its own before it stops. Starting the direct chat yourself starts the count again. Range: 1 to 100. Default: 5.

Protocol limits: hub authentication

Minimum ADC password challenge length
The shortest password challenge (salt), in Base32 characters, an ADC hub may send before DC++ answers it with your password hash. A short challenge makes a captured answer easier to crack. If a hub sends a shorter one, the password is not sent, the hub is disconnected and automatic reconnection to it is turned off. Lower this only for older hub software you trust. Range: 2 to 39 (39 is the 24 bytes the ADC specification requires). Default: 10, as in DC++ 0.884.

Protocol limits: NMDC hubs

Default encoding for NMDC hubs
The character encoding (code page) used for NMDC hubs that have no encoding of their own in their favorite hub properties: for hub chat, nicks, private messages, search results and direct connections. Windows default uses the system code page. An NMDC hub uses one encoding for everything, and DC++ doesn't guess it from each line: for a hub that uses UTF-8, choose 65001 (UTF-8) here or in the hub's favorite properties, or names and messages with non-English characters will be garbled. Default: Windows default.

Protocol limits: protocol resource limits

These limits protect DC++ from using too much memory, too many connections or too many network packets. The defaults suit normal use: lower values can turn away legitimate traffic, and higher ones use more resources and leave DC++ more open to flooding. Changes apply to new connections and packets without restarting DC++. The partial file list limits are on the Transfers and hashing tab.

Queued protocol data limit
The most protocol data DC++ keeps waiting to be sent on one connection, in KiB. A connection that would exceed it is closed. Minimum: 1 KiB. Default: 16384 KiB (16 MiB).
Concurrent peer connection limit
Incoming connections from other users are turned away while this many connections to users (transfers and direct private chats, in either direction) are open. Hub connections don't count. Minimum: 1. Default: 512.
Incoming connection flood window
The period over which incoming connection attempts are counted for each IP address. Within it, an address may make twice the maximum regular upload connections per user plus 8 attempts, and at least 32; further ones are turned away. Minimum: 1 millisecond. Default: 10000 milliseconds.
Global UDP rate window
The period over which incoming search results (UDP packets) are counted for the global packet limit. Minimum: 1 millisecond. Default: 1000 milliseconds.
Global UDP packet limit
The most incoming search result packets processed in each global UDP rate window; more are ignored. Minimum: 1. Default: 2000.
Per-peer UDP packet limit
The most incoming search result packets processed from one IP address in each per-peer UDP rate window; more are ignored. Minimum: 1. Default: 500.
Per-peer UDP rate window
The period over which incoming search result packets are counted for each IP address. Minimum: 1 millisecond. Default: 10000 milliseconds.
Tracked UDP peer limit
How many IP addresses the per-peer UDP limit keeps track of. While the table is full and no entry has expired, packets from new addresses are ignored. Minimum: 1. Default: 4096.
Encrypted UDP packet limit
The largest encrypted search result packet DC++ decrypts, in bytes. A valid packet is also at least 32 bytes and a multiple of 16 bytes (the AES block size). Minimum: 32 bytes. Default: 4096 bytes.
Stored encrypted UDP key limit
How many keys of your recent searches DC++ keeps to decrypt encrypted search results; the oldest is dropped first. Minimum: 1. Default: 64.
BBS boards per hub limit
The most bulletin boards (BBS0) kept for each hub. Further boards the hub announces, or that its posts refer to, are ignored, with a single status message. Range: 1 to 1000. Default: 100.

Other: offline message outbox

Keep messages for offline users and send them later
A private message written to a user who is offline is kept in the message outbox and sent when the user is next online. View > Message outbox lists the waiting messages and has the same switch. Default: off.
Maximum retained messages
How many messages the outbox keeps. It applies to new messages and retries; messages already waiting keep their deadlines. Range: 1 to 10000. Default: 500.
Maximum message size
The longest message the outbox keeps, in KiB. It applies to new messages and retries. Range: 1 to 64 KiB. Default: 16 KiB.
Pending messages expire after
How many days a message waits for its recipient before it is dropped. It applies to new messages and retries; messages already waiting keep their deadlines. Range: 1 to 365 days. Default: 7 days.

Other: hub user lists

Default user icon size
The size of the icons in hub user lists: 16, 20, 24, 28, 32, 40 or 48 pixels, scaled for the display's DPI. Each favorite hub can choose its own size in its Favorite Hub Properties, or with the Icons list beside the user filter of its window; choosing Default there uses this setting (or that of the hub's favorite group). Changing this updates open hubs that use it. A hub that is not a favorite keeps a size chosen in its window only while the window is open, unless the hub is added to Favorites. Default: 16 pixels.

Other: System Log

Maximum System Log items
How many recent messages DC++ keeps for the System Log window, shown when it is opened or its style changes. Lowering it drops the oldest messages. The window itself also holds at most 96 KiB of text. Range: 1 to 1000 messages. Default: 100 messages.

Other: country database

DC++ shows the country of users from a local GeoLite2 Country database, which covers IPv4 and IPv6. While Guess user country from IP (Settings > Appearance) is on, DC++ downloads a new database once a day, and tries again six hours after a failed attempt; File > GeoIP database update updates it at once. The download shows in the transfer view, where it can be canceled, and a failed update keeps the database in use. Changing the options below starts an update.

Download URL
The HTTPS address of a Country .mmdb file, or of a .tar.gz archive containing one. Public GitHub release files work and need no login. Default: the GeoLite2 Country database DC++ Experimental publishes on GitHub (https://github.com/iceman50/exp-geoip2/releases/latest/download/GeoLite2-Country.mmdb).
Download directly from MaxMind (testing override)
Downloads the database from MaxMind with the account ID and license key below, instead of from the download URL. Turning it off goes back to the URL. If a license key was saved before this option existed, it is on. Default: off.
MaxMind account ID
Your numeric MaxMind account ID, used when downloading directly from MaxMind.
License key
Your full MaxMind license key, used when downloading directly from MaxMind. It is stored encrypted for your Windows account, so it can't be read from the settings file on another account or computer.

Other: password lock

The password lock hides DC++ behind a password while you are away from the computer. When DC++ is locked, its window shows only a password box: the menu, the toolbar, the open tabs, the transfers and the status bar are hidden, keyboard shortcuts do nothing, the taskbar shows no tab previews, the window title doesn't name the hub or user in view, and balloon pop-ups say what happened without showing the message. Hubs, searches, uploads, downloads and hashing keep running as usual. Enter the password and press Enter, or click Unlock, to use DC++ again. Links, magnets and balloons you click while it is locked open once it is unlocked.

Type /lock in any chat window to lock DC++ straight away.

The lock keeps other people at your keyboard out of DC++. It doesn't encrypt anything: your settings, logs and downloads stay readable to anyone who can use your Windows account, so lock Windows itself (Windows key + L) for real protection. If you forget the password, close DC++ and remove the LockPassword line from DCPlusPlus.xml in your settings folder; DC++ then starts without a lock password.

Set password, Change password, Remove password
Sets the lock password, which the options below need. Changing or removing it asks for the current password first. DC++ stores only a salted PBKDF2-SHA256 hash of the password, never the password itself. The change takes effect at once; removing the password also turns the options below off.
Lock DC++ when it is minimized
Locks DC++ whenever its window is minimized, to the taskbar or to the tray. Default: off.
Lock DC++ when it starts
Starts DC++ locked. Hubs you were connected to reconnect as usual behind the lock. Default: off.
Ask for the lock password before exiting
Asks for the lock password whenever DC++ is closed, from the window, the tray or the taskbar, so nobody else can stop it. This applies whether or not DC++ is locked. Shutting down or signing out of Windows is never held up. Default: off.
