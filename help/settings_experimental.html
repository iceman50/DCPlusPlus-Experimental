Experimental

This page is a top-level Settings category immediately above Plugins and collects experimental sharing, transfer, hashing, RTF0, defensive protocol, and interface controls. The controls are divided among the Chat and sharing, Transfers and hashing, Protocol limits, and Interface tabs.

Compression and large file lists

Prefer Zstandard over zlib when the peer supports both
Use Zstandard for downloads from clients supporting the experimental ZST1 extension on ADC or NMDC. Older clients continue to use the existing compression. Full lists from supporting clients use compressed XML instead of bzip2. Requires Compress transfers. The default is off. The preference affects new download requests; supporting peers may still request Zstandard uploads.
Cache file lists on disk and load file entries on demand
Build a compressed disk index when opening XML, bzip2, or Zstandard lists. Directory metadata remains available, while file entries load when a directory is visited and are released when leaving it. The original list is retained. The first open builds the index; later opens reuse it unless the source changes. Search, queue matching, ADL rules, and directory downloads include unloaded entries. One very large directory still needs memory for its own entries. This uses additional disk space and defaults to off. Applies to newly opened lists.

Hub user lists

Default user icon size
The global size for hub user-list icons: 16, 20, 24, 28, 32, 40 or 48 pixels, scaled for display DPI. The default is 16. Each favorite hub can override this in Favorite Hub Properties or the Icons dropdown beside its user filter. Choosing Default removes the hub override and inherits the global or favorite-group setting. Changing the global default updates open hubs that inherit it. Non-favorite hubs keep a selected size only for the current window; adding the hub to Favorites saves that choice.

System Log

Maximum System Log items
Maximum number of recent messages retained for the System Log window and available when it is opened or restyled. Lowering the value discards the oldest retained messages. The visible RichEdit buffer also retains its independent 96 KiB safety limit. Minimum: 1 message. Maximum: 1000 messages. Default: 100 messages.

Application theme

The theme editor has moved to Appearance > Themes. The Interface tab provides a shortcut to the Themes page, which now includes interface colors, chat formatting and a live RichEdit preview.

Rich text and temporary shares

Enable ADC RTF0 CommonMark chat
Advertise ADC RTF0 support on hubs and direct CCPM connections and render its safe CommonMark dialect. Supporting chats provide the RTF0 editor and drag-and-drop attachments.
Enable temporary file sharing in chats
Allow unshared files dropped on any connected ADC or NMDC hub or private chat—and files selected by the RTF0 editor—to be hashed and exposed by exact TTH for that route. Plain and RTF0 chat displays keep the magnet URI visible and clickable and show its human-readable file size; RTF0 routes may additionally render formatted attachments and inline images. Disabling this prevents new temporary shares and makes existing temporary entries unavailable to search or transfer while retaining them in the management list until removed or the application exits.
Insert dropped image files as inline media
Use RTF0 inline-image syntax for recognized BMP, GIF, ICO, JPEG, PNG, TIFF, and WebP files when the chat supports RTF0. Plain ADC and NMDC chats always receive an ordinary magnet link.
Rich text message size limit
Maximum UTF-8 size of an incoming or outgoing ADC RTF0 rich text message, in KiB. Larger incoming messages are replaced with an omission notice; larger editor drafts cannot be inserted into chat. Minimum: 1 KiB. Default: 64 KiB.
Clickable chat link length limit
Maximum URL or magnet URI length that will be turned into a clickable chat link. Longer links remain visible as plain text. Minimum: 1 character. Default: 256 characters.
Maximum temporary shares
Maximum number of temporary RTF0 attachments retained for the current application session. Adding another entry removes the least recently used entries first. Minimum: 1. Default: 256.
Automatically remove temporary shares after
Set the lifetime in minutes, measured from the most recent addition of the file to a chat draft. Default: 0 (no automatic expiration). Changes apply to existing entries too. Expiration stops new searches and downloads through the temporary share; it does not delete the local file, remove posted messages, or affect normally shared files. Expired entries are cleaned up every minute.
Active temporary shares
Lists the session-only files currently addressable by exact TTH, including their route and local path. These files appear in search results only on the hub or CCPM route where they were added, remain absent from file lists and share totals, and can be downloaded by TTH only from that route. Remove selected entries, clear the full list, or refresh file availability from here.

Multi-connection transfers (MCN)

Maximum regular download connections per user
Limits simultaneous regular ADC MCN1 download connections opened to one user. The peer's CO limit is also respected; a missing CO field or CO0 means that the peer has no separate per-user limit. Multiple connections can download different files, and may also download different segments when segmented downloading is enabled.
Maximum regular upload connections per user
Limits simultaneous regular ADC MCN1 upload connections accepted from one user. This value is advertised to MCN1-capable peers. Upload slots count unique regular upload users rather than their physical MCN connections, and excess connections are redistributed when another user needs a slot.
Priority connection
MCN1 automatically maintains one additional connection for partial file lists and files smaller than 64 KiB. It is outside both regular per-user connection limits and the normal upload/download slot totals. Its transfer role is fixed for the life of the connection; full file lists, file trees, and larger files remain on regular connections.

Hashing and share database

Maximum hash speed
Limits file hashing speed in MiB/s. Zero means unlimited.
Hashing worker threads
Maximum number of CPU workers used to calculate independent Tiger Tree Hash blocks for one file. File input remains sequential and SFV checks remain ordered. DC++ may use fewer workers when the file has too few blocks, the computer exposes fewer logical processors, or the fixed 256 MiB pipeline-memory limit would be exceeded. Use one thread to retain serial hashing. Default: 2 threads. Minimum: 1. Maximum: 64.
Hash database write batch size
Number of SQLite hash database row changes grouped into one transaction. Larger values improve bulk hashing throughput; smaller values commit newly hashed files sooner.
Verify hash database on startup
Runs a quick SQLite integrity check when the hash database opens.
Compact hash database after rebuild
Compacts SQLite storage after a hash database rebuild.
Use cached share tree on startup
Loads a validated cached share tree before the background filesystem refresh completes.
Verify / Full check / Optimize / Compact
Runs hash database maintenance immediately. Verify uses SQLite quick_check, Full check uses integrity_check, Optimize updates query planning hints, and Compact checkpoints the WAL and reclaims unused space.

Protocol resource limits

These limits protect DC++ from excessive memory, connection, and packet use. The defaults are recommended for normal use. Lower values can reject legitimate traffic; higher values increase resource usage and exposure to denial-of-service traffic. Changes apply to new operations without restarting DC++.

Queued protocol data limit
Maximum unsent protocol data retained for one socket, in KiB. The socket is disconnected when another write would exceed the limit. Minimum: 1 KiB. Default: 16384 KiB.
Concurrent peer connection limit
New incoming peer connections are rejected when this many incoming and outgoing transfer or private-message connections already exist. Hub connections are not included. Minimum: 1. Default: 512.
Incoming connection flood window
Time span used to count incoming peer connection attempts from each IP address. The allowed burst is derived from the multi-connection upload setting. Minimum: 1 millisecond. Default: 10000 milliseconds.
Global UDP rate window
Time span used by the global incoming search-result UDP packet limiter. Minimum: 1 millisecond. Default: 1000 milliseconds.
Global UDP packet limit
Maximum incoming search-result UDP packets processed during the global UDP rate window. Minimum: 1. Default: 2000.
Per-peer UDP packet limit
Maximum incoming search-result UDP packets processed from one IP address during the per-peer UDP rate window. Minimum: 1. Default: 500.
Per-peer UDP rate window
Time span used to count incoming search-result UDP packets separately for each IP address. Minimum: 1 millisecond. Default: 10000 milliseconds.
Tracked UDP peer limit
Maximum number of IP addresses retained by the per-peer UDP limiter. New addresses are ignored while the table is full and no expired entries can be removed. Minimum: 1. Default: 4096.
Encrypted UDP packet limit
Maximum encrypted search-result UDP packet accepted for decryption. Valid packets must also be at least 32 bytes and aligned to a 16-byte AES block. Minimum: 32 bytes. Default: 4096 bytes.
Stored encrypted UDP key limit
Maximum recent search encryption keys retained for decrypting SUDP results. Oldest keys are discarded first. Minimum: 1. Default: 64.
Generated partial file list limit
Maximum uncompressed XML size generated in response to a partial file-list request, in KiB. Minimum: 1 KiB. Default: 65536 KiB.

Private Send (experimental PFT1)

Disabled by default. Private Send offers a selected file directly from private chat without a search result, file list, or public magnet. Both clients must support the same experimental draft, use an ADCS hub and a fresh TLS 1.2+ direct chat (TLS 1.2 requires ECDHE and authenticated encryption). Manual contact verification is temporarily off by default for testing. After enabling, reconnect an existing direct chat to negotiate support. Open Private Send... from the chat menu, or click the file icon in the PM status bar when the connection and any required contact verification are ready.

Clear list dismisses finished, cancelled, declined, expired and failed transfers for this contact. Active and paused transfers stay in the list, and saved files are kept.

Require manual contact verification (off for testing)
Default: off. Leave unchecked on both clients to test without exchanging CIDs and fingerprints. Connections remain encrypted, but contact identity is not independently verified. Turning this on requires both contacts to use Verify contact and cancels transfers without an approved matching fingerprint. Testing does not save contacts as verified.
Offer expires after
Lifetime of a new outgoing offer before acceptance. Default: 15 minutes. Range: 1–1440 minutes.
Accepted transfer expires after
Maximum lifetime after acceptance. Default: 1440 minutes. Range: 1–10080 minutes. The earlier peer deadline wins. Existing deadlines are never extended by settings changes.

Recipients explicitly accept each file. Received files undergo full hash verification and Windows attachment policy before being saved below PrivateSend\Received in the profile's local data directory. They are never opened or shared automatically. Pause permits recipient-initiated resume for up to 30 minutes within the hard deadline, with at most three attempts. Disabling the feature or forgetting a verified contact revokes transfers.

Expiry removes access and incomplete received files; it never deletes the sender's original or a completed received file. Sessions do not survive restart. PFT1 is a proposed identifier, and stable interoperability and independent security review remain release gates.

Direct private-message channels (CCPM)

These controls govern automatic recovery of an encrypted direct private-message channel. Each failed attempt uses an exponentially longer delay, with random jitter to keep two identical clients from retrying in lockstep.

Initial automatic reconnect delay
Delay before the first automatic reconnect and the starting point for exponential backoff. Minimum: 1 second. Maximum: 3600 seconds. Default: 5 seconds.
Maximum automatic reconnect delay
Upper bound for the exponential reconnect delay. A value below the initial delay is raised to match it when Settings is applied. Minimum: 1 second. Maximum: 3600 seconds. Default: 60 seconds.
Stable connection reset time
Time a direct channel must remain connected before a later disconnect resets the accumulated automatic-attempt count. Minimum: 1 second. Maximum: 86400 seconds. Default: 60 seconds.
Maximum automatic reconnect attempts
Number of automatic attempts permitted before reconnection is paused. Starting the direct channel manually resets the attempt budget. Minimum: 1. Maximum: 100. Default: 5.

Interface: GeoLite2 Country testing

Enable Download directly from MaxMind (testing override) to use your numeric MaxMind account ID and full license key instead of the hosted country database URL. The key is encrypted for your Windows account. Turning off the override restores the URL in Appearance. Existing testing configurations with saved keys retain direct MaxMind downloads automatically. Save to start an update, or use File > GeoIP database update.
